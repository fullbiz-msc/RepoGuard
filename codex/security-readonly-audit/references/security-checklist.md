# Минимальное покрытие аудита: 20 проверок

Этот список дополняет анализ путей данных и бизнес-логики из SKILL.md. Это задания для анализа, а не разрешение включать защиту, менять настройки или запускать атаки. Для каждого пункта отрази в отчёте статус и доказательства: **защита подтверждена в проверенном охвате**, **найден дефект**, **не проверено** или **неприменимо**. Один пункт может иметь несколько статусов для разных компонентов. Для «не проверено» укажи недостающее свидетельство, для «неприменимо» — причину.

Наличие настройки не доказывает её применение на production. Ссылайся на файл и строку либо на явно предоставленное свидетельство работы среды. Неизвестное не отмечай как успешную проверку.

| № | Область | Что установить по доступным материалам |
|---|---|---|
| 01 | Вход и сессии | Проверка личности, восстановление доступа, завершение/отзыв сессий, ограничение перебора; применение MFA к критичным аккаунтам с учётом модели угроз. Различай аутентификацию и права после входа. |
| 02 | API-ключи и секреты | Отсутствие приватных ключей в клиентском коде, bundle, исходниках, логах и примерах; серверное хранение и минимальные полномочия. Публичный идентификатор не объявляй секретом только из-за названия. Значения маскируй. |
| 03 | Доступ к БД | Отсутствие прямых привилегированных подключений из клиента, минимальные права учётной записи, сетевые ограничения и разделение данных пользователей/организаций. Неизвестные firewall и настройки сервера не считай проверенными. |
| 04 | HTTPS | TLS для внешних соединений, проверка сертификатов исходящих запросов, правила перенаправления и доверия proxy. Не делай живых запросов; отсутствие конфигурации помечай как пробел. |
| 05 | Пароли | Использование специализированного password hashing с солью и настройками стоимости, проверка средствами библиотеки; отсутствие открытых паролей, обратимого хранения и быстрых обычных хешей для паролей. Внешний провайдер входа может делать локальное хранение неприменимым. |
| 06 | Серверная валидация | Типы, диапазоны, длины и схема всех недоверенных входов; проверка на сервере независимо от формы. Неожиданные поля, mass assignment, отрицательные значения, null, большие размеры и обход клиентских ограничений. |
| 07 | XSS | Путь недоверенных данных до HTML, атрибутов, JS и URL, контекстное экранирование, опасные DOM-вставки и очистка разрешённого HTML. Одного поиска innerHTML недостаточно. |
| 08 | Административный доступ | Серверная проверка роли и полномочий каждого административного endpoint, экспорта и действия. Скрытая кнопка, нестандартный URL и переданный клиентом user_id/tg_id не заменяют авторизацию. |
| 09 | SQL и запросы | Параметры драйвера для значений, разрешённые списки для динамических идентификаторов; сырые SQL/NoSQL-фрагменты, сортировка и фильтры. Наличие ORM само по себе не исключает инъекции. |
| 10 | Переменные окружения | Источники конфигурации, обязательные значения, опасные fallback/default, попадание env в клиентскую сборку и публичную выдачу, разделение сред. Перед чтением .env/.env.*/файлов секретной конфигурации получи явное согласие на точные пути по SKILL.md. До ответа и при отказе продолжай независимый аудит; значения окружения отметь непроверенными. Наличие .env не доказывает защищённость. |
| 11 | Лимиты ресурсов | Ограничение частоты и стоимости входа, восстановления, экспорта и тяжёлых операций; размеры запросов, таймауты, пагинация, очереди и повторы. Учти обход через разные экземпляры приложения и недоверенные proxy-заголовки. Нагрузку не создавай. |
| 12 | CORS | Разрешённые origin, credentials, проверка origin и поведение wildcard/null с учётом назначения API. CORS — браузерное ограничение чтения ответа, а не замена авторизации, CSRF-защите или защиты от запросов с сервера. |
| 13 | Заголовки безопасности | Применимость CSP, HSTS, frame-ancestors/X-Frame-Options, nosniff и подходящей Referrer-Policy; область действия и исключения. Проверяй соответствие приложения политике, а не только наличие строки. HSTS требует корректного HTTPS; не предлагай preload/includeSubDomains без оценки доменов. |
| 14 | Cookies и CSRF | HttpOnly для недоступных JS сессионных cookies, Secure при HTTPS, подходящий SameSite, Domain/Path и жизненный цикл. Для запросов с автоматически передаваемыми учётными данными — защита изменяющих действий от CSRF; SameSite не объявляй универсальной заменой проверки. |
| 15 | Файлы | Ограничения размера, типа и количества, проверка содержимого вместо доверия расширению/MIME клиента, имена и пути, права доступа при скачивании, запрет исполнения, архивы и распаковка. Разрешённые форматы и лимиты определяются продуктом; «5 МБ, jpg/png/pdf» не универсальное требование. |
| 16 | Цены и платежи | Расчёт суммы/валюты/скидок на сервере, связь с заказом и владельцем, подтверждение у провайдера/подписанным webhook, идемпотентность, атомарность и конкурентные списания, повтор/порядок событий, возвраты и бонусы. Не доверяй success-странице или клиентскому paid=true. Реальных платежей не выполняй. |
| 17 | Production и диагностика | Debug, stack trace, отладочные маршруты, тестовые аккаунты, подробные ошибки и секреты в логах/телеметрии. Различай настройку разработчика и реально используемый профиль запуска. |
| 18 | Зависимости | Закреплённые версии, доступные advisories, затронутость и достижимость уязвимого пути, transitive зависимости и источники пакетов. Не запускай npm audit/установку/обновление в этом режиме. Если актуальные источники недоступны, не заявляй отсутствие CVE. |
| 19 | История Git | Если история доступна и входит в разрешённый охват, проверь удалённые из текущего кода секреты без вывода значений. Избегай необработанного git log -p и широких дампов: используй инструмент, скрывающий значения до вывода, либо отметь эту часть непроверенной. Укажи охват истории и shallow-копии. Отзыв/ротация — рекомендация владельцу, не действие аудитора. Удаление из HEAD не отзывает ключ. |
| 20 | Доказательства и проверка исправлений | Сведи находки, меры защиты, пробелы и приоритеты. Для дефекта предложи безопасный регрессионный сценарий и критерий успеха. Отдельно укажи, что тесты не запускались, изменения не применялись и исправления не подтверждены. Не приписывай иллюстративные числа и результаты реальному проекту. |

В отчёт включи компактную таблицу `№ / область / статус / компонент и свидетельство / пробел или действие`. Подробные дефекты опиши отдельно по формату находки, связывая их с номерами проверок. Общая рекомендация без доказанного пути — не подтверждённая уязвимость. «Защита подтверждена» относится только к перечисленным компонентам и доступным свидетельствам.

После отчёта не переходи к исправлениям автоматически. Явное поручение пользователя на конкретные исправления — отдельная задача реализации вне read-only режима RepoGuard; оно не разрешает автоматически остальные рекомендации, публикацию, ротацию секретов, миграции, активные атаки или нагрузку.
